# WORK-CLEAN-START 驾驶记录

给接手这项工作的会话看。事实以 `buildbeat status --repo . --work WORK-CLEAN-START` 和 Git 为准，这里只记那里查不到的。

## 怎么做的

- 会话亲自写代码。每段开一轮运行（`run --new`），停在实现步后在运行的工作树里写、提交，再 `run --run <RUN> --adopt <sha> --by claude-code` 交回验证和 Codex 只读审查。
- 驾驶用本机已装的 5.5.0（`buildbeat`），不用工作树里正在改的代码。
- 每段开跑前把 `run-config.yaml` 里验证脚本的参数改成段号并提交。
- 审查问题由会话记 `accept` 并修；所有者只在合并决定处批准。

## 第一段（已合入，RUN-CLEAN-START-02）

work.md 之外定下的细节：

- 一项工作从哪算起：最后一次改它 work.md 的那个提交；工作的配置里可写 `base` 覆盖。
- 工作自己的记录文件夹永远算在 `allowedPaths` 之内。
- 这种运行在事件和运行记录里多一个字段 `pass: true`。
- 进程被杀的审查，由同一工作的下一次送审记为取消并清掉检出。
- 验证步骤挪动了检出的 HEAD，这一轮记失败（审查第一轮的 P1）。
- 兼容测试从 `v5.5.0` 标签取原版运行时；浅克隆会跳过。
