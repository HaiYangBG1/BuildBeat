# WORK-CLEAN-START 结果

运行时现在只做四件事：记、验、审、批。代码由会话自己写、自己提交，`buildbeat review` 在那个提交上跑项目的验证并请只读的 AI 审查，`buildbeat decide --work` 把人的批准记在这个提交上；只认当前这一种写法。三段分别经所有者批准，合入会话分支 `claude/open-source-project-review-9d8d4f`（合并提交 `41ada89`、`29f081b`、`5c512e7`），没有推送，没有合入 `main`，没有发版。

数字：`src` 从约 13,200 行到 7,985 行；测试从 459 项到 336 项；`SKILL.md` 8.8 KB；随包文件 103 个到 99 个；删了 88 个历史文件；独立审查三段共 6 轮（上限 12）。

## 定了什么

- 工作说明里的 11 项按推荐执行，见 `work.md` 和 `decisions.jsonl`（A-WORK-CLEAN-START-2）。
- 项目配置里的 `release:` 只是默认的回读命令；只有工作自己的配置声明了 `release:`、或已经记过回读的工作，才必须回读通过才能关窗。审查者认为应该全部强制，所有者裁决维持（`review-findings.jsonl`，指纹 `f8e029d0c58ebdfc`）。
- 同一项工作再次送审时，只清这个版本自己的临时检出；旧版本运行留下的工作树不动。旧版本留下的还在等决定的运行，会被新的送审取代。
- 没有 work.md 的文件夹：有记录，或有这个版本自己不会放的 Markdown/YAML 文件，显示 `LEGACY`；只有 `run-config*.yaml`、`notes.md`、`env-facts.md` 的是新草稿。源码里不出现旧文件名。
- 只记回读、不审查的项目，配置里可以只写 `release:`。
- 以后每版的发布证据写在 `CHANGELOG.md` 那一版的发布段里，不再单独存证据文件。
- 文档链接检查不查 `delivery/work/` 里的记录：它们是当时的记录，不回头改。
- 这项工作自己的 `verify.sh` 中途改过基线核对：没动过的文件追溯必须和基线一致，改写过的旧归属只能少不能多，删掉的跳过。
- `lessons.md` 删了三条只讲已删功能的：Run 停下来没人知道（通知、停顿检测、清理）；预算是刹车不是墙；中途审批点被会话自己批、换个说法认不出（分诊门、收敛判断）。

## 剩下什么

- 发 6.0.0、推送、合入 `main`：等所有者另说。发版前要做的：试点仓只读核对（在跑的工作、没关的旧格式工作、截图和回读的真实用量），需要所有者同意才能读。
- README 的配图没动：首图、"记录是顺手留下的"、"看证据"三张图上还画着"修复"那一步，和文字对不上，发版前换图。
- 路径里的 `v2` 改名、不再维护 `v2` 分支：工作说明里写明另做。
- 读者测试：下一项工作。
- 小毛病没改：被锁挡住的送审会先打印一行 `reviewing …` 再报错；`status` 把更早一轮里已经修掉、没人裁决的问题仍算进 `unadjudicated`（和 5.5.0 一样）；批准后 `status` 立刻显示 `MERGED`。
- 这项工作自己的 `run-config.yaml` 是给 5.5.0 驾驶用的旧写法，留作记录；本仓以后的工作用 `delivery/run-config.yaml`。
