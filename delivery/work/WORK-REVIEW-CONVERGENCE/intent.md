# Intent:让「review 不收敛」真的认得出同一个问题,并补齐 3.3.0 的文档遗漏(WORK-REVIEW-CONVERGENCE)

## 为什么做

3.3.0 发布后复查发现三处问题:

1. **「修过的 finding 又出现」几乎认不出来**。判断靠指纹,指纹 = 严重度 + `summary` 原文的 hash;reviewer 的 summary 习惯带 `文件:行号`,措辞也每轮略有不同。回放本机 4 个仓、160 个 Run、161 轮 review:按指纹一次重复都没有。但真实发生过同一个问题连审三轮——某仓一个 Run 里「完整 diff 包含两个允许范围外的文件:`docs/…md:73`、`tests/…test.mjs:293`」在第 1、2、3 轮反复出现,第 2 轮写成「仍包含」,第 3 轮写成「包含本次允许范围之外的改动」;另一个仓有「root 管理者与服务身份的所有权要求互相冲突」→「root 管理者与服务身份仍未被代码强制分离」。现在这类循环只能靠「阻断数比上一轮多」或 6 轮上限兜住。
2. **`lessons.md` 过时**(它随 npm 包发出去):教训 14 的「解药」还写着「每 Run 默认 2 轮封顶」「经 `reviewTriage` 人分诊后才派 fixer」,与 3.3.0 矛盾;3.3.0 的起因(中途审批几乎都由驾驶会话自己批、起不到把关作用)没有按项目规矩回灌成一条教训。
3. **发布 runbook 少两句**:3.3.0 本地候选用 Node 22 打包、CI 用 Node 24 + npm 11.19.0,gzip 层不同导致 integrity 对不上,只能靠解压比对证明一致;另外所有者本机有两份全局 CLI(版本管理器下一份、Homebrew 下一份),发布后只更新了一份,会话实际用的仍是旧版。

## 目标

- review 收敛判断改用「同一问题」判定:同指纹,或文件锚点集合相同且描述相近,或描述高度相近;只用于收敛判断,**不改指纹本身**(已有的 dismiss / accept 裁决照旧按指纹生效);
- 判定规则用上面的真实回放验证:命中真实重复,且在 161 轮里不误报;
- `lessons.md` 教训 14 的解药改成现行机制,新增一条 3.3.0 的教训(审批点被驾驶会话自批 + 同一问题换说法认不出);
- `docs/RELEASING.md`:候选用与发布 workflow 相同的 Node / npm 打包,或以解压后的 tar 摘要比对;发布后的检查清单加一条「本机每一份全局安装都换到新版(`which -a buildbeat`)」;
- 3.3.0 发布证据里「本机全局 CLI → 3.3.0」更正为两份都已更新的事实;
- CHANGELOG `Unreleased` 同步,为 3.3.1 做准备。

## 非目标

- 不改 finding 指纹算法,不改 worker 合同(`findings[]` 仍只要求 `severity` + `summary`);
- 不改 6 轮上限、不改模板的 `reviewTriage` 默认值;
- 不处理其他项目的 run 配置(底座那边在 meta 仓单独改);
- 不 merge、不 push、不发版(这三步由所有者另行授权)。

## 验收条件

- 新增 `sameIssue(a, b)`(或同等命名)及单测:覆盖同指纹、同锚点 + 措辞改写、无锚点的高相似改写、同文件不同问题不算、不同文件相近措辞不算;测试用例用通用化的示例文字,不带任何真实项目内容;
- 收敛测试补一例:第 2 轮把上一轮修过的问题换个说法再报一次 → 停 `review-not-converging`,理由里同时列出前后两条;原有收敛测试全过;
- 回放结论(命中哪些、误报几次)写进 notes.md,数字可复现(回放脚本不进包、不进仓库,只记方法与结果);
- `npm test`、`npm run check:docs`、`npm run test:plugin`、`npm run test:pack-firstrun`、`npm run test:envelope` 全绿;
- 指南(工作流中英、审批中英)、CHANGELOG 对「又出现」的表述改为「同一问题(同指纹或描述相近)」。

## 止损线

- 最多 2 个 Run;review 累计最多 4 轮(`budgets.reviewRoundsPerWork: 4`);
- 墙钟超过 4 小时未到合并决定,停下先问人是否拆分。
