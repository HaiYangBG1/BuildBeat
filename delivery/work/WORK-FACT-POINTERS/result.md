## 定了什么

- 开工前四项按推荐（A-WORK-FACT-POINTERS-1）：提交写在节标题里，节内用反引号写指针，路径可以只写后半段；没开跑的比当前 HEAD，开过跑的比最近一轮的起点，已关的不比；写了行号的只看那几行；只提醒，不拦。
- 审查后，所有者改定（2026-10-25）：变了的引用附上这段时间改过这个文件的提交，标明是文件的提交（输出 `<c> commits to the file`，JSON 为 `file: {commits, latest}`）；变没变仍按行判断。这一条与已接受的 work.md 里"改动它的提交"和 `commits` / `latest` 字段不同，以这里为准，work.md 不改。
- 解析 Git 输出时固定补丁前缀和会改变输出的设置；一项工作的现状固定为四次 Git 调用，再加每个变了的文件一次。
