# Intent:把评审剩下的问题一次收干净(WORK-REVIEW-CLEANUP)

## 为什么做

3.1.0 修掉了评审里最伤人的运行时问题,还剩一批没做:两个已裁决延后的 P2、一个排队痛点、以及几项让项目越来越难维护的积累。
所有者要求一个 Work 收掉:

1. **两个延后的 P2**:run-config 的「显式 null 报错」规则把 `cache: null`(一直表示不开缓存)也拒了;YAML 多行列表项用了新的映射判定,改变了本就非法输入的报错措辞(违背计划)。
2. **每仓只能跑一个 Run**:不同功能的 Run 也要排队,试点里排过 3 小时 23 分钟;但测试会抢固定端口/共用数据库的项目并行会互相打架。**所有者已拍板:加开关,默认不变。**
3. **测试泄漏临时目录**:32 个测试文件建临时仓库不清理,跑 3 遍测试会在 `$TMPDIR` 留下几百个目录、近百 MB(含 git worktree)。
4. **lessons 编号引用失效**:3.0.0 给 lessons 重新编号后,代码与 SKILL 里按编号引用的地方有的已指错(如 `decisions.js` 的「#18」、`metrics.js` 的「#8」)。
5. **`docs/` 顶层混着 ~28 份历史文档**:计划、试点记录、各版发布证据与现行文档平铺在一起;npm 包靠 `package.json` 里 13 行排除规则维持,新增一份历史文档默认就会被打进包。
6. **`SKILL.md` 438 行、47 KB,每次触发整份装载**:会话真正每次都要的是「一句话 → 调什么」的驾驶手册,方法论正文按需读即可。

## 目标

- 两个 P2 按原计划口径修正;
- run-config 新增并行开关:打开的 Work 可以与其他 Work 的 Run 同时跑,同一 Work 的 Run 仍互斥;不打开的一律照旧独占仓库;
  两种模式混用时互不越界(独占 Run 在跑时,并行 Run 起不来;并行 Run 在跑时,独占 Run 起不来);被杀进程留下的标记可被安全回收;
- 测试跑完不在临时目录留下任何东西;
- lessons 引用改为按标题引用,不再依赖编号;
- 历史文档归档到子目录,npm 包改为白名单,**包内文件清单与 3.1.0 完全一致**;
- `SKILL.md` 压到 200 行以内:保留触发条件、驾驶手册、红线摘要与索引,方法论正文拆到按需读取的参考文件,内容不丢。

## 非目标

- 不改默认并发行为、不改预算/锁/台账语义;
- 不改 lessons 正文与编号本身,不回改 CHANGELOG 历史条目的文字(只修链接路径);
- 不做 `drive()` 拆分、`parseFlags` 布尔参数、CodeQL 分支等评审里未列入的项;
- 不 merge、不 push、不发版。

## 验收条件

- P2:`cache: null` 重新表示不开缓存,`base: null` 等仍报错;多行列表项的判定与报错恢复为修改前版本(以冻结的旧解析器对比);
- 并行:集成测试证明两个开了开关的不同 Work 的 Run 确实同时在跑;同一 Work 的第二个 Run 被挡;独占 Run 在跑时并行 Run 被挡,反之亦然;持有者已死的并行标记不挡路;
  未开开关时行为与现在逐条一致(现有并发相关测试不改仍通过);
- 测试:跑一遍 `npm test` 前后,`$TMPDIR` 下新增的测试目录为 0;
- 代码/SKILL/预设里不再有按编号引用 lessons 的地方,且有测试守住;
- `npm pack --dry-run` 的文件清单与 3.1.0 发布包逐一相同;所有相对链接有效;
- `SKILL.md` ≤ 200 行,移出的每一节都能从 `SKILL.md` 的索引直达;docs 检查全绿;
- `npm test`、`npm run check:docs`、`test:pilot`、`test:plugin`、`test:pack-firstrun` 全绿;CHANGELOG `Unreleased` 同步。

## 止损线

- 最多 2 个 Run;review 累计最多 4 轮(`budgets.reviewRoundsPerWork: 4`);
- 墙钟超过 6 小时未到合并决定,停下先问人是否拆分。
