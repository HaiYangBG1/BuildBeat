# 跨仓总览：在主仓一条 status 看全部代码仓

## 目标

常见的工作区形态是"一个主仓 + 若干代码仓"：主仓放各项工作的 run 配置，配置里的 `repo:` 指向代码仓；工作说明、决定、审查记录和运行台账在代码仓里。今天要知道"哪里在跑、什么在等我批、下一步做什么"，得在每个仓分别跑一次 `status`，而主仓自己的 `status` 只看得到配置，会把代码仓里正在运行的工作显示成"待开跑"并提示 `buildbeat run`。

本工作让人和会话在主仓用一条命令看到所有仓里需要处理的事项，每一项显示它在真实所在仓的状态，附带能在当前目录直接执行的命令；并修正主仓单仓 `status` 的上述误报。

依据（2026-10-07，试点工作区：主仓 + 5 个代码仓）：6 个仓共约 120 项工作，其中绝大多数已关窗或已合并；主仓 `status` 输出 250 行，并把一项正在代码仓运行的工作显示为 `READY_TO_RUN`、提示 `buildbeat run`。

## 待所有者确认的对外名字（接受本说明即确认）

| 项 | 提议 | 备选 |
|---|---|---|
| 跨仓查看 | `buildbeat status --repo <主仓> --all-repos`（可加 `--work <ID>`、`--json`） | 不加参数，主仓 `status` 默认带上代码仓；或重复写 `--repo` |
| 找仓规则 | 主仓本身 + 主仓 `delivery/work/` 下 run 配置里 `repo:` 指向的仓 + 主仓下一层含 `delivery/work/` 的 git 仓；按真实路径去重，不递归 | 只认 `repo:`；只认下一层目录 |
| 默认隐藏的"已了结" | CLOSED、CANCELLED，以及已合并且 run 配置没有 `release:` 段的工作（没有剩余动作）；每个仓只给数量 | 全部列出 |
| JSON 形状 | `{"repos": [{"repo", "works", "settled"}], "pending": [...], "warnings": [...]}` | — |

## 范围

包含：`status` 的 `--all-repos` 模式与主仓单仓误报修正（运行时 overview 与 CLI 输出）、对应回归测试、`SKILL.md` 查看进度一行、现行中英指南中讲接手与查看进度的部分、`templates/v2/AGENTS.md`（如需一句话）、CHANGELOG `Unreleased`。

不包含：改变 Run 在哪个仓执行、在仓之间同步或复制 work.md、递归发现多层仓、远端仓库、通知改动、npm 发布与合并到 main（各自单独决定）。

## 行为要点

### 1. `--all-repos`

- 按上表规则找仓；`repo:` 指向的路径不存在、不是 git 仓或配置读不了时，输出一行警告，其他仓照常显示，命令不因此失败。
- 合并规则：主仓里的一项工作，若其 run 配置的 `repo:` 指向另一个仓，且那个仓有这项工作的记录（同名 `delivery/work/<ID>/` 或运行台账），就只在那个仓下显示一次，状态、Run、审查问题与决定都取自那个仓；提示里的 `--config` 用主仓那份配置。那个仓还没有记录时，留在主仓下显示，并注明"运行目标：<仓>"。
- 输出顺序：先列所有仓的待人决定（与现在 `status` 的待批块相同，命令带正确的 `--repo`），再按仓列未了结的工作（运行中、停滞、待开跑、待接受、工作说明已改动、已合并待收尾等），最后每个仓一行"已了结 N 项（CLOSED a / CANCELLED b / 已合并无收尾步骤 c）"。
- 所有提示命令都能在当前目录直接复制执行：仓路径与配置路径相对当前目录给出。
- `--work <ID>` 只看这项工作在各仓的合并结果；`--run` 与 `--all-repos` 同时出现时报错并说明用 `--work`。
- `--json` 给全部工作（含已了结），按上表形状；文本模式才隐藏已了结。
- 只读：不在任何仓写文件、不取锁、不压缩台账。

### 2. 主仓单仓 `status` 的误报修正

- 不加 `--all-repos` 时，主仓里一项工作若其 run 配置的 `repo:` 指向另一个仓、且那个仓有这项工作的记录，这一行显示那个仓里的状态并标注所在仓，提示命令同上；那个仓没有记录时保持现状并注明运行目标。只看一层，不递归。
- 其他工作和代码仓自己的 `status` 输出不变。

## 验收

- `verify.sh` 全过：Node 回归、文档检查、Bash 信封、Claude 插件、安装后首跑、本 Work 范围内 `git diff --check`。
- 回归测试用临时目录里真实的 git 仓搭"主仓 + 两个代码仓"，覆盖：
  1. 主仓配置指向代码仓、代码仓里有等待决定的 Run：`--all-repos` 只在代码仓下列出一次，批准 / 拒绝命令在主仓目录可直接执行；
  2. 只在主仓的草稿工作列在主仓下；只在代码仓、主仓没有配置的工作也列出；
  3. CLOSED、CANCELLED、已合并且无 `release:` 段的工作只计数不列出；已合并且配了 `release:`、尚未关窗的列出；
  4. `--json` 形状与全部工作；`--work` 过滤；`--run` 与 `--all-repos` 同用报错；
  5. 主仓单仓 `status` 对情形 1 显示代码仓里的状态，而不是 `READY_TO_RUN` 与 `buildbeat run`；
  6. `repo:` 指向不存在的路径：一行警告，其他仓照常；
  7. 运行前后所有仓的文件快照一致（只读）。
- 三路独立只读审查（运行时与命令、文档与界面、测试与打包）无未裁决的 P0/P1。
