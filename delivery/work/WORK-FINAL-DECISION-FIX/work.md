# 合并决定点能接修复

## 目标

Run 停在合并决定（`enter-wait-merge`）时，人常在这一步才发现一个小问题。4.0 在这里只能批准或拒绝：`run --adopt` 明确拒绝合并决定点，拒绝则结束本轮。想带着修复再审，只能开新一轮、从 build 重来，已经过验证和审查的候选与上下文都要重建。

依据：试点工作区 4.0 发布后的 14 个真实 Run 中，有 5 次因为在合并决定点想补一处修复而新开 Run，每次重做 build；2026-10-07 本仓 WORK-CROSS-REPO-STATUS 在合并决定点人工发现一处回归，同样只能选择带病批准、在下一项工作里修，或整轮重来。

本工作让合并决定点能直接接住修复：修复成为新候选，从 verify 继续，经过 review 后回到合并决定；旧候选上的批准请求随之作废，预算与历史证据保留。

## 待所有者确认的对外名字（接受本说明即确认）

| 项 | 提议 | 备选 |
|---|---|---|
| 接纳手工修复 | 沿用 `buildbeat run --config <c> --run <RUN> --adopt <sha> --by <name>`，合并决定点也接受 | 新命令 |
| 退回给修复者 | `buildbeat decide --repo <r> --run <RUN> --action fix --reason <要修什么> --by <name>`，只在合并决定点可用 | 不做 |
| 决定记录 | 合并决定点被接纳修复时记 `adopted`（同现有 adopt），退回时记 `decision: "fix"` 并带原因 | — |

所有者 2026-10-07 选择两种做法都做。

## 范围

包含：运行时（合并决定点的接纳与退回、候选换绑、状态与待批卡片、通知中的回复命令）、对应回归测试、Skill 中"已手修并提交"一行与合并决定相关说明、审批与恢复两篇中英指南、CHANGELOG `Unreleased`。

不包含：已批准（SUCCEEDED）后的重新打开、3.x 旧 Run（仍按迁移说明回到原运行时）、自动合并或推送、改变 review 收敛与预算规则本身。

## 行为要点

### 1. 合并决定点接纳手工修复

- 条件同现有 adopt：Run 正在等合并决定；工作树干净；`<sha>` 是工作树当前 HEAD（完整读取 Git，不信声明）；另外要求新提交是当前候选的后代，不允许改写历史。
- 改动仍受 `allowedPaths` 约束，越界与现有规则一样不能成为候选。
- 记录 `adopted` 决定，回答合并决定请求；候选换成新提交；从 verify 继续，之后 review（有上次审查的候选时按增量范围审），再回到合并决定。
- 旧候选不能再被批准：针对旧候选的批准命令按"批准已过期"拒绝。
- review 轮数照常计入 `reviewRoundsPerWork`；已有证据保留在台账中，合并检查只认当前候选的证据（现有规则）。

### 2. 退回给修复者

- 只在合并决定点、且 run 配置有 fixer 时可用；没有 fixer 时拒绝，并提示改用手工修复后 `--adopt`。
- 原因以人提出的问题写入本 Work 的审查问题台账（严重度 P1，已接受），fixer 的输入里能看到；之后 verify、review，再回到合并决定。
- 不扣除也不退还预算；退回本身不算一轮 review。

### 3. 呈现

- 合并决定的状态卡、待批列表与通知，在批准 / 拒绝之外列出这两种做法及可复制的命令（没有 fixer 时只列手工修复）。

## 验收

- `verify.sh` 全过：Node 回归、文档检查、Bash 信封、Claude 插件、安装后首跑、本 Work 范围内 `git diff --check`。
- 回归测试覆盖：合并决定点接纳修复后从 verify 继续、经 review 回到合并决定、最终批准绑定新候选；旧候选的批准被拒；非后代提交、工作树不干净、越界改动分别被拒；退回给修复者时 fixer 收到原因、之后回到合并决定；没有 fixer 时退回被拒且提示手工修复；review 轮数照常累计；3.x 旧 Run 行为不变；状态卡与通知列出新命令。
- 三路独立只读审查（运行时与命令、文档与界面、测试与打包）无未裁决的 P0/P1。

## 实施计划

1. 在决定与接纳逻辑中允许合并决定点的 adopt，加入后代检查，回答请求后从 verify 恢复。
2. 加入 `decide --action fix`：校验 fixer 存在，写入人提出的问题，派 fixer。
3. 状态卡、待批、通知的回复命令。
4. 回归测试。
5. Skill、审批与恢复指南（中英）、CHANGELOG。

## 止损

范围变化需要新的决定。审查轮数上限 6 轮（run-config `budgets.reviewRoundsPerWork`），跨本 Work 所有 Run 累计。
