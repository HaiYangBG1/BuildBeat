# WORK-OVERVIEW-SPEED 结果

一次 `status` 里，每个仓库的运行台账只解析一次，各项工作的运行、成本和工作编号扫描共用这一份；「候选进没进主干」改成每个仓库只跑一次 `git rev-list` 查，不再每个候选起一个 `merge-base`。试点工作区的跨仓总览从 30.8 秒降到 4.3 秒（`--json` 从 29.4 秒降到 3.9 秒），输出逐字节相同。候选 8d06449 经 RUN-OVERVIEW-SPEED-01 验证一次通过，codex 只读审查 0 条；所有者批准（D-RUN-OVERVIEW-SPEED-01-2）后，候选先以 c9719e0 合入工作分支，再经 PR #120 以 merge commit 5593a23 进 main。未发版。

## 定了什么

- 台账缓存只放在一次 `status` 的上下文里，命令结束就丢，写台账的路径照旧各开各的。
- 主干历史超过 64 MB 列不出来，或候选不是完整提交号时，退回 `merge-base`。
- 已有测试只改了一处断言：跨仓起进程的那条，从「`merge-base` 2 次」改成「`rev-list` 每个所属仓库 1 次、`merge-base` 0 次」。
- 剖析还找到第三处：转到代码仓的工作在全仓视图里会附带单项详情。改掉会改变输出，所有者定不做。
- 慢的原因之一只在本机：PATH 里第一个 `git` 是双推包装器，每次起进程要 106 毫秒。减少起进程的次数在哪台机器上都有用，所以不去绕过包装器。
