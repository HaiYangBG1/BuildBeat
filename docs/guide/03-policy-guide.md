# 批准前检查什么

[English](03-policy-guide.en.md)

批准一个提交前，运行时固定检查这几件事，不能配置成更松：

- 工作说明已被接受，而且接受的就是这个提交里那份 work.md。work.md 改过，旧的接受就失效，要重新接受。
- 这个提交有通过的验证证据，是运行时自己跑出来的。
- 审查是在这个提交上做的，没有未裁决的严重问题（默认 P0、P1；`maxReviewSeverity: P3` 时 P2 也算）。
- 配置了 `requireScreenshot: true` 时，这个提交有验证留下的截图。
- 批准命令写的完整提交号，就是等待决定的那个提交。

缺任何一样，或者核对不了，批准被拒，并说明缺什么。检查条件在送审时记进这一轮，之后改配置不影响已经送审的这一轮。

项目的安全、接口、界面和上线要求，写在项目规范和真实的验证命令里。服务端分支保护和宿主隔离由各自的平台负责。
