# 跨会话接续

[English](11-session-handoff.en.md)

关闭旧会话前，将目标、决定、未验证范围和下一步写入项目；检查 Git 和 `status`。没提交的改动要么提交，要么写明在哪。

新会话读取项目 AGENTS.md、这项工作的 work.md、决定与 status。能从记录查到的事实自行核对，沿用仍有效的授权；等人决定的那一轮还在，不用因为换了会话重新送审。

问一件事整体到哪了，用 `buildbeat status --repo . --all-repos --work <ID>`：工作说明或 result.md 里写了关系行（`- follows:`、`- split from:`、`- related:` 加工作编号）的工作，会被串成一条线，跨仓列出每项的阶段；反方向的关系自动推出，找不到的标为 `NOT_FOUND`。正文里只是提到的编号单列为 mentions 和 mentioned by，不算进这条线。手里只有任务、决策或合并请求编号时，用 `--ref <编号>` 找写了 `- ref: <编号>` 的工作。

接手一段代码时，先用 `buildbeat history --repo . --path <文件>[:<行>[-<行>]]` 查它来自哪项工作：运行时对这些行做 blame，再按三种确定的线索对上工作——提交落在某一轮审查记录的起点到被审提交之间、提交信息带 `Work: <ID>`、提交改动了 `delivery/work/<ID>/`。三种都没有的提交，标题里只写了一个、并且在 `delivery/work/` 下有文件夹的工作编号时，也算这项工作的，标成 `via subject`：这条线索较弱，因为标题常顺带提到别的工作，写了两个以上编号的不算。仍追不到的行单独计数。以后的提交用 `buildbeat hooks install --repo .` 装的钩子自动补 `Work:` 标记。读列出的 result.md 和 work.md 再动手。

开工前，或者接手一项写好一阵的工作时，先看 `buildbeat status --repo . --work <ID>` 里的 `facts:` 那块。"已核实的现状"的标题写了核实时的提交号、正文用反引号写了 `路径`、`路径:行` 或 `路径:起-止` 的，运行时会把这些代码和工作的起点对比：还没送审的比当前 HEAD（工作配置里写了 `base` 的比它），送审过的比最近一轮的起点。写了行号的只看这几行有没有被改，没写行号的看整个文件。改了的列为 changed，并附上这段时间改过这个文件的提交数和最近一个（是文件的提交，不一定都动了引用的那几行）；文件删了、对不上或对上多个文件的列为 not found。这些事实要重新核实，更新现状和标题里的提交号后重新接受。`accept` 和 `check` 遇到这种情况也会打印一行 `warning: facts …`，但不拦。已关窗的工作不比对：它的现状本来就是开工前的样子，做完后什么成立看 result.md。

status 显示 `COMMITTED` 的工作没送审过、也没关窗，但当前分支上已经有改了 `delivery/` 以外文件、能追到它的提交（提交信息带 `Work: <ID>`，或者同一个提交改了它的文件夹）。这只说明有提交，不说明做完了：还在做的接着做；做完了就用 `buildbeat decide --repo . --work <ID> --action close --draft` 按这些提交写一份 result.md 初稿，对照 Git 和工作说明改好，删掉第一行和每一处 `<fill in`，再关窗。初稿原样或还留着 `<fill in` 时，关窗会被拒绝。

已关窗的工作先读它的 result.md：做成了什么、定了什么、剩下什么转去了哪里、写进了项目哪些文档。起草新工作前，先在已关工作的 result.md 里搜相关的结论和遗留，把用得上的写进新 work.md 的"起因"。

主仓管理多个代码仓时，先运行 `buildbeat status --repo . --all-repos`。它只读查看主仓，以及主仓下一层含 `delivery/work/` 的 Git 仓，按真实路径去重，不递归。读不了的仓给出警告，其余照常显示。

待人决定先列出，随后按仓显示未了结工作；CLOSED、CANCELLED 和已合并且没有声明上线的工作只计数，后者计为 `merged, not closed`，单仓 `status` 会提示它去收口。声明了上线、尚未关窗的已合并工作仍显示。`--json` 返回 `{repos: [{repo, works, settled}], pending, warnings}`，包含已了结工作；`--work <ID>` 筛选各仓里的这项工作，`--run` 不能与 `--all-repos` 同用。每个仓的工作、审查和决定都记在它自己的 `delivery/work/` 里，提示命令里的仓路径相对当前目录，可以直接执行。

没有 work.md、只有旧版本文件的工作显示 `LEGACY`：读它的文件夹，或者写 result.md 关窗。

换工具时重新配置命令、鉴权和输出合同；接手事实可以复用，具体工具执行能力需要验证。换人时同步提交、记录和权限，说明当前推进人及下一步。

换机器只能通过 Git 同步长期事实。`.buildbeat/runtime/` 不随 clone 走：已结束的各轮有记录可读，还在等决定的那一轮要在新机器上重新送审。

跨会话演示不等于所有工具组合都已验证。
