# 证据与效率读数

[English](06-evidence-guide.en.md)

证据来自 Git 和真实执行：种类、候选、日志摘要、结果、等级、产生者及起止时间。通过、失败、未验证分开；旧候选的证据不能给新候选放行。

保留 L0–L4 历史等级，默认命令证据为 L2。等级标签不自动证明生产验收；项目必须提供实际运行环境的证据。生产探针已移出主产品；合并后的上线回读见[工作确认与决策](07-approval-guide.md)。

UI 交付在 run-config 写 `requireScreenshot: true`。verify 运行时，环境变量 `BUILDBEAT_SCREENSHOT_DIR` 指向工作树外一个新的空目录；verify 把真渲染截图（png、jpg、jpeg、webp）写进去，每张记为绑定当前候选的截图证据（文件摘要）。verify 成功却没有截图按失败处理；合并检查要求当前候选有截图；reviewer 输入、待决定卡和通知列出截图路径与摘要。开关随 Run 冻结，复用缓存的 verify 一并沿用来源截图。

原始日志在 .buildbeat/runtime/；终态 run-record、工作决定和审查裁决在 delivery/work/。摘要不是原始日志备份，按项目要求保留后者。

status 展示工作成本、证据完整性、审批等待、修复次数和耗时。它们是本地派生读数，不是 Token/金额账单。验证缓存明确标注来源，只复用成功且匹配的树、命令、信封；依赖外部变化的检查不启用。

check --step 不进入正式台账，其结果必须在 Run 中重现。实时输出和耗时也不是验收结论。

减法的验证比较完成耗时、人工介入、重复执行与恢复结果；脚本回归不能外推真实 AI 速度。
