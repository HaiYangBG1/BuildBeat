# 指挥台 — 你(指挥)怎么驱动各 session

> 忘了怎么开场就看这页。每个 session 一开就自动读 `AGENTS.md` + `pm/NOW.md`,你基本只需说「**开工 / 接着做 / 看板上 X 该你了**」,剩下它自驱。
> **每个 session 第一次对话先设定角色**:「你是产品/全栈/测试,负责……(照 `AGENTS.md` §1 域表说)」;之后就不用再说了。

| Session | 在哪开(cwd) | 你的一句话 | 它自动做啥 |
|---|---|---|---|
| **产品** | `pm/` | 「把需求X拆工单」/「验收X」 | 定一个覆盖多个子项的工作包、维护决策收件箱、更看板、按包记 decisions、收敛候选 hash 集;review-ready 后派一次 reviewer |
| **全栈** | 工作区根 | 「看板上需求X该你了,开工」 | 读工作包+契约 → 在范围内持续实现 → 每提交过机器闸 → 只记实现语义 delta → 工作包/里程碑时状态带 hash + CHANGELOG |
| **测试** | `<被测仓>/` | 「跑X的E2E + 走查设计」 | 黑盒 E2E + 带图设计走查 → 直接提 bug → 给里程碑核查提供证据 |

## 编排循环
1. **产品** 拆好 + 你拍板 **⛔Gate1 规格** → 2. 产品写设计 brief(要求单 HTML 可渲染)→ 你喂设计工具出稿 → **`bash scripts/design-preview.sh <期号>` 真渲染 → 你点过关键流后拍板 ⛔Gate2** → 3. **全栈** 实现(先改 PROTOCOL、每提交过机器闸、写者自发现问题先收敛进同一实现语义清单;只有改冻结对外语义/不可逆副作用才提前 `risk-delta`)→ 4. **测试** E2E + 带图走查 → `HEAD=candidate`、工作树干净、L3/渲染证据绿、无待修项 → milestone reviewer 静默全核**一次** → P0/P1 合并修完后 closure **一次** → **⛔Gate3 你合并** → 5. 部署 → **⛔Gate4 你批上线** → 回产品收尾。

> **会话不按子任务交还接力棒**:每轮先认领 `objective / in_scope / terminal_condition`;文档、commit、reviewer、status 都可能只是包内步骤。范围内仍有安全工作就继续,不等你再说“继续”。
> **审批只分三档**:跨 Gate/扩范围/改冻结契约/不可逆外部动作/风险接受才 `STOP_NOW`;冻结前可逆选择进看板收件箱,到 Gate 默认一次批 2–5 个(确实只有 1 个就单项);事实、推导约束、归档/status/P2 等无需批。
> **人批预算**:每个工作包、每道 Gate 默认只发 1 个批量请求。你只答一部分或要解释时,会话保持同一决策包继续说明,不会重新包装成“第二次审批”;不阻塞的工作照常继续。
> 决策包收敛后,产品域先落 `pm/decisions.md` 一行再回写各处;部分回答只更新收件箱,不为 `3/14 → 11/14 → 14/14` 制造三条台账。**线上是什么版本别问会话、别信文档,跑 `bash scripts/bus-check.sh` 看实况**。
> **三轨制**:小改快轨 / 单功能标准轨 / 契约变更重轨(`pm/changes/` 提案)。本期走哪轨看 `pm/NOW.md`。
> **核查门不按任务数收费**:首次 milestone 前不启动 reviewer;review-ready 后每工作包每 Gate 默认 1 次 milestone,P0/P1 合并修完后 1 次 closure,P2 不复核。reviewer 单次静默核完再返回,不播报中间 findings。同一 candidate 复用结论;返回前 hash 变化就标 `SUPERSEDED` 并停止,不得边改边 delta。
> **4 个 Gate 不可自动跨过**;reviewer 批准 ≠ 你合并。你只是节拍器,信息全在 repo 里流动,不用你搬运。
