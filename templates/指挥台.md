# 指挥台 — 你(指挥)怎么驱动各 session

> 忘了怎么开场就看这页。每个 session 一开就自动读 `AGENTS.md` + `pm/NOW.md`,你基本只需说「**开工 / 接着做 / 看板上 X 该你了**」,剩下它自驱。
> **每个 session 第一次对话先设定角色**:「你是产品/全栈/测试,负责……(照 `AGENTS.md` §1 域表说)」;之后就不用再说了。

| Session | 在哪开(cwd) | 你的一句话 | 它自动做啥 |
|---|---|---|---|
| **产品** | `pm/` | 「把需求X拆工单」/「验收X」 | 拆工单、更看板、记 decisions、收敛候选 hash 集;里程碑派一次 reviewer |
| **全栈** | 工作区根 | 「看板上需求X该你了,开工」 | 读看板+契约 → 实现 → 每提交过机器闸 → 只记实现语义 delta → 状态带 hash + CHANGELOG |
| **测试** | `<被测仓>/` | 「跑X的E2E + 走查设计」 | 黑盒 E2E + 带图设计走查 → 直接提 bug → 给里程碑核查提供证据 |

## 编排循环
1. **产品** 拆好 + 你拍板 **⛔Gate1 规格** → 2. 产品写设计 brief(要求单 HTML 可渲染)→ 你喂设计工具出稿 → **`bash scripts/design-preview.sh <期号>` 真渲染 → 你点过关键流后拍板 ⛔Gate2** → 3. **全栈** 实现(先改 PROTOCOL、每提交过机器闸、实现语义记同一清单;高风险变化才核 `risk-delta`)→ 4. **测试** E2E + 带图走查 → 固定候选 hash 集 → milestone reviewer 四方一致全核**一次** → **⛔Gate3 你合并** → 5. 部署 → **⛔Gate4 你批上线** → 回产品收尾。

> 你拍的每一锤,产品域先落 `pm/decisions.md` 一行再回写各处;**线上是什么版本别问会话、别信文档,跑 `bash scripts/bus-check.sh` 看实况**。
> **三轨制**:小改快轨 / 单功能标准轨 / 契约变更重轨(`pm/changes/` 提案)。本期走哪轨看 `pm/NOW.md`。
> **核查门不按任务数收费**:同一候选 hash 复用结论;文件数/草稿/P2 不触发全审;候选有变化只核 delta。
> **4 个 Gate 不可自动跨过**;reviewer 批准 ≠ 你合并。你只是节拍器,信息全在 repo 里流动,不用你搬运。
