# pm/changes/ —— 变更提案(治跨域 race + drift)

> 跨域变更(尤其动**契约/需求/多域**的)**不要直接抢改看板/契约文件** —— 先在这写一个独立 change。冻结前允许在已批准目标内持续收敛草案和补证;一次冻结决策后先把批准的 delta 合并进 canonical,再让新语义进入共享实现。

## 何时用
- **重轨**改动:跨期 / 契约变更 / 多域大改。小改快轨、单需求标准轨,都不用建 change。

## 流程
1. **开草案** → 新建 `pm/changes/<yyyymmdd>-<短名>.md`(用下方模板),标 `草案收敛`。建草案本身不等于申请人批。
2. **收敛** → 在已批准 objective/in_scope 内自查、补证、做可抛弃原型;把需要人取舍的独立决策变量汇入当期看板「决策收件箱」(默认 2–5 个一包,确实只有 1 个就单项)。验收条目和推导约束不逐项问。
3. **冻结** → 到 Gate 或关键路径确实被阻塞时,一次提交决策包:批 / 改 / 否。收敛后在 `../decisions.md` 记一行,先把批准的 Delta 合并进 canonical(`contracts/PROTOCOL.md` / 需求文档),再把 change 标 `已冻结`。冻结前草案不得被冒充 canonical,也不得让未批语义进入共享实现。
4. **实现** → 各域按已冻结 change 的"分工"动手,轻量机器闸每次提交、受影响测试按变更批次;只把实现期新增的失败态、不可达状态、默认值/阈值、fail-closed 方向记进同一份「实现语义清单」,不为每个小任务新建完整审查报告。
5. **候选** → 收敛一个精确的里程碑候选 hash 集。实现中若要修改**已冻结**契约/鉴权/租户/Secret/fail-closed/持久化或产生不可逆副作用,STOP_NOW,只对对应 `base..candidate` 做 `risk-delta` 定向核并回流拍板;普通可逆实现细节继续。
6. **核查 + 归档** → 对里程碑候选做一次完整核查;P0/P1 清零后,产品域确认 canonical 与已冻结、已实现语义一致,change 移到 `pm/changes/archive/`。同一候选 hash 合并前复用结论,不重复全审。

## 模板(复制改)
```md

- 状态:草案收敛 / 待冻结 / 已冻结 / 实现中 / 已归档

- 工作包:<当期看板 objective 或锚点>
- 冻结基线:<未冻结 / decisions.md 日期+决策包>

## Delta(改什么 —— 逐条标 ADDED / MODIFIED / REMOVED)
```
