# 指挥台 — Builder 怎么驱动 v2 工作（忘了怎么开场就看这页）

> 本仓运行 BuildBeat v2。每个 session 一开就自动读 `AGENTS.md`；活动工作在 `delivery/`。你基本只需说下面这几句话，命令由会话调、不用你手敲。

## 日常六句话

| 你想干什么 | 说什么 | 会话背后调什么 |
|---|---|---|
| 看现在到哪了、该谁动 | 「当前进度」/「待办是什么」 | `buildbeat-v2 overview --repo .`（每个 Work 的阶段 + 下一步）+ `observe status` |
| 看有什么等我批 | 「有什么要我拍板」 | `buildbeat-v2 inbox --repo .`（每条附可复制的下一句） |
| 立一件新事 | 「开个 Work：〔一句话目标〕」→ 看完说「接受」 | 建 `delivery/work/<ID>/intent.md + plan.md` → `accept`（digest 绑定） |
| 让它干活 | 「开工」/「再来一轮」 | `buildbeat-v2 start --config … --attempt new`（自动编号、自动作废旧等待，停在合并决定） |
| 它是不是卡了 | 「怎么样了」/「卡住了吗」 | `buildbeat-v2 status --repo . --run <RUN>`（耗时、历史中位数、最后输出、STALLED） |
| 拍板 | 「批准 / 拒绝〔RUN-ID〕」；分诊时「这条接受，那条不算」 | `approve` / `reject` / `findings adjudicate`；批准仅表示 merge-ready，合并/push/部署逐项另说 |

其他：生产报警看 `delivery/observe/intents/` 草稿 → 「fix_now / schedule / dismiss」；上线用 `release-readback` 预设开一个 Run，「我做完了」就是批准 `enter-apply-readback`；「打扫卫生」= `gc --repo .`（先看计划再 `--apply true`）。

## 视角开场白

| AI 视角 | 在哪开（cwd） | 你的一句话 |
|---|---|---|
| **产品** | 工作区根 | 「把当前目标收成一个 Work」/「验收」——定 intent/plan、维护决策收件箱、按决策包记 `pm/decisions.md` |
| **全栈** | `<代码仓>/` | 「〔WORK-ID〕该你了，开工」——授权范围内实现，Run 停在合并决定回人批 |
| **测试** | 工作区根 | 「验〔RUN-ID〕候选」——对精确 candidate 独立核验，报告落所属 Work 目录 |

## 域回复怎么写

面向你收口统一「已做 → 未做 → 下一步」，各一句；证据紧跟事项。下一步只写一条：下一棒是谁、需要你确认什么、或「我继续做，暂不交棒」。
